## 모바일 가로 넘침 판정

초기 Chrome `--window-size=390,844` 캡처에서는 홈과 필요 평수 계산기의 오른쪽이 잘려 보였습니다. 그러나 해당 방식은 macOS Chrome 내부 레이아웃 폭을 500px로 유지한 채 390px 이미지만 저장할 수 있어 실제 모바일 판정에 사용할 수 없었습니다.

Chrome DevTools Protocol의 모바일 장치 폭 강제 설정으로 다시 검사했습니다.

| 화면 | 내부 폭 | 문서 폭 | 가로 넘침 | 화면 밖 요소 |
|---|---:|---:|---|---:|
| 홈 | 390px | 390px | 없음 | 0개 |
| 필요 평수 계산기 | 390px | 390px | 없음 | 0개 |

- 홈 제목, 설명, 세 CTA는 실제 390px 화면 안에 정상 표시됐습니다.
- 계산기 제목은 두 줄로 자연스럽게 줄바꿈됐습니다.
- 안내문, 입력창, 선택 버튼의 잘림이 없었습니다.
- 결론: 모바일 가로 넘침은 실제 제품 결함이 아니라 초기 캡처 방식의 측정 오류였습니다. 불필요한 레이아웃 수정은 적용하지 않았습니다.

## 푸터 클릭 영역

작은 글자 링크의 안쪽 `span`에만 최소 높이를 주면 실제 바깥 링크의 클릭 영역은 19px로 남는 것을 브라우저 측정으로 발견했습니다. 바깥 링크 자체와 개인정보 동의 링크에 모바일 최소 클릭 높이를 적용했습니다.

| 모바일 링크 | 수정 전 실제 클릭 높이 | 수정 후 실제 클릭 높이 |
|---|---:|---:|
| 직원 로그인 | 19px | 44px |
| 협력사 로그인 | 19px | 44px |
| 개인정보처리방침 | 13px | 44px |
| 이용약관 | 13px | 44px |

데스크톱에서는 `sm:min-h-0`으로 기존 푸터 간격을 유지합니다.
