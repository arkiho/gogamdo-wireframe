## 쉬운 용어 설명

- **크롤링**: Google 로봇이 주소를 방문해 내용을 읽는 과정입니다.
- **색인**: 읽은 페이지를 Google 검색 결과 후보 목록에 저장하는 과정입니다.
- **200**: 페이지가 정상적으로 열리는 상태입니다.
- **301 리디렉션**: 옛주소로 방문한 사람과 Google을 새주소로 자동 안내하는 영구 주소 이전입니다.
- **403**: 페이지나 파일은 있을 수 있지만 접근 권한이 없어 서버가 문 앞에서 거절하는 상태입니다.
- **404**: 해당 주소에 페이지가 없어, 주소에 찾아갔지만 가게가 사라진 것과 같은 상태입니다.
- **canonical(대표주소)**: 같거나 비슷한 여러 주소 중 Google에 원본으로 취급해 달라고 알려주는 대표 주소 표지입니다.
- **사이트맵**: Google에 공개 페이지 주소를 알려주는 사이트의 주소 안내 목록입니다.

## 확인된 핵심 원인

1. 정상 포트폴리오·인사이트 상세 페이지 32개가 자기 주소가 아니라 홈페이지를 canonical로 표시했습니다.
2. 정적 사이트맵 페이지 모두가 요청한 날을 수정일로 표시했습니다.
3. 의미가 확실한 과거 주소의 301 이전 규칙이 부족했습니다.
4. 개발 서버가 함수형 Vite 설정을 실행하지 않고 함수 자체를 설정처럼 사용해 화면을 띄우지 못했습니다.
5. 설정되지 않은 분석도구 자리표시자를 브라우저가 실제 주소처럼 요청했습니다.

## 적용한 수정

- 검색에 공개하는 정상 SPA 경로에만 자기 URL canonical 및 `og:url` 주입
- 없는 페이지·없는 동적 레코드·`/404`·로그인/관리자 경로에는 canonical을 제거하고 `noindex` 적용
- 포트폴리오·인사이트 상세 페이지 self-canonical 적용
- 사이트맵 정적 페이지의 거짓 `lastmod` 제거
- 날짜가 없는 동적 콘텐츠에는 거짓 오늘 날짜를 넣지 않도록 수정
- 과거 포트폴리오 목록 `/works/`만 현재 목록 `/portfolio`로 301 연결
- `/works/education/`, `/works/corporation`, `/press/`처럼 현재 목록과 의미가 정확히 같지 않은 범주형 주소는 404 유지
- 실제 공개 포트폴리오와 이름이 일치하는 과거 프로젝트 주소만 해당 `/portfolio/p/{id}`로 301 연결
- 알 수 없는 프로젝트 주소는 억지로 홈에 보내지 않고 404 유지
- 함수형 Vite 설정을 개발 서버 시작 전에 정상 해석
- 오래된 분석도구 HTML 자리표시자 제거; 기존 런타임 분석 기능은 설정값이 있을 때만 로드
